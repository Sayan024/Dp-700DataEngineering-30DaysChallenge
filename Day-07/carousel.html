Essential PySpark DataFrame Operations
Key PySpark functions tested in DP-700 Data Engineering scenarios
# Column Projection & Filtering
df_filtered = df \
  .select("order_id", "customer_id", "amount", "status") \
  .filter(col("amount") > 100) \
  .filter(col("status") == "COMPLETED")

# Conditional Column Derivation (when / otherwise)
from pyspark.sql.functions import when, col
df_tier = df.withColumn(
  "customer_tier",
  when(col("amount") >= 500, "PLATINUM")
  .when(col("amount") >= 200, "GOLD")
  .otherwise("SILVER")
)
⚡ Lazy Evaluation Concept
Transformations like .filter() and .withColumn() do NOT execute immediately. Execution occurs only when an Action is called.
Transformations (Lazy): select, filter, groupBy, join, withColumn
Actions (Eager): count, show, collect, write, saveAsTable

🪟 PySpark Window Ranking (Deduplication)
from pyspark.sql.window import Window
from pyspark.sql.functions import row_number, desc

w_spec = Window.partitionBy("customer_id") \
  .orderBy(desc("updated_at"))

df_deduped = df.withColumn("rn", row_number().over(w_spec)) \
  .filter("rn == 1") \
  .drop("rn")

V-Order Optimization
OPTIMIZE SOLUTION→Optimize a Lakehouse table with V-Order
V-Order: Microsoft Fabric's Write Optimization
What it is, why it matters, and how it accelerates reads
⚡ What is V-Order?
A write-time optimization for Delta Parquet files in Microsoft Fabric. It applies special sorting, dictionary encoding, and compression algorithms to Parquet file structures.
  • Enabled by default in all Fabric Spark engines
  • 100% compliant with standard open-source Delta Lake
  • Drastically accelerates Power BI DirectLake mode
  • Speeds up SQL Analytics Endpoint T-SQL queries
⚙️ How to Control V-Order
# Check or enable via PySpark session
spark.conf.set("spark.sql.parquet.vorder.enabled", "true")

# Disable if writing data for non-Fabric engines
spark.conf.set("spark.sql.parquet.vorder.enabled", "false")
💡
Exam Rule: When asked how to achieve maximum Power BI DirectLake performance on Lakehouse Delta tables — **V-Order** is the top answer!

File Compaction
OPTIMIZE SOLUTION→File Compaction with OPTIMIZE & Z-ORDER
Fixing the Small File Problem
How OPTIMIZE merges thousands of small files into large ~1 GB files
📦 OPTIMIZE (Bin-Packing)
Merges thousands of small Parquet files (e.g. 2 MB each) into larger, uniform files (~1 GB). Eliminates file system scanning overhead.
-- Run compaction in Spark SQL
OPTIMIZE gold_sales;
🎯 Z-ORDER (Multi-Dimensional Index)
Co-locates related data in the same physical files based on filter columns. Enables Data Skipping.
-- Compact + Z-ORDER by frequent WHERE columns
OPTIMIZE gold_sales
ZORDER BY (customer_id, order_date);

Table Maintenance
MAINTAIN TABLES→VACUUM command & storage retention
VACUUM & Retention Safety
Cleaning physical storage vs preserving Time Travel history
🧹 What VACUUM Does
Physically removes unreferenced data files older than the retention threshold from storage.
-- Default retention: 7 days
VACUUM sales_gold;

-- Retention period override (e.g. 168 hours = 7 days)
VACUUM sales_gold RETAIN 168 HOURS;
⚠️
CRITICAL EXAM TRAP: VACUUM breaks Time Travel!
Once physical files are deleted by `VACUUM`, you CANNOT query timestamps or versions prior to the vacuumed threshold!
🔒 Retention Period Best Practice
Keep default 7 days unless storage costs dictate aggressive cleanup. Never set retention to 0 hours in production!

⏳ Delta Time Travel

SELECT * FROM sales_gold VERSION AS OF 4;

-- Query by Timestamp
SELECT * FROM sales_gold TIMESTAMP AS OF '2026-07-22 10:00:00';

# PySpark Time Travel
spark.read.option("versionAsOf", 4).table("sales_gold")
🧬 Schema Evolution (mergeSchema)
# Automatically append new columns without failing
new_data_df.write.format("delta") \
  .mode("append") \
  .option("mergeSchema", "true") \
  .saveAsTable("sales_gold")

Schema Enforcement (Default): Delta Lake rejects writes if new DataFrame columns don't match the table schema, preventing data corruption!

Exam Traps
DP-700 CAUTION→PySpark & Delta Lake exam traps
Top 4 PySpark & Delta Exam Traps ⚠️
🚫
Trap 1: "V-Order breaks open-source Delta readers" ❌ WRONG. V-Order is 100% open-source Delta Parquet compliant — non-Fabric engines can read V-Ordered tables fine.
🚫
Trap 2: "Time Travel works after VACUUM 0 HOURS" ❌ WRONG. VACUUM physically deletes underlying Parquet files from OneLake storage, breaking Time Travel queries!
🚫
Trap 3: "PySpark transformations execute immediately" ❌ WRONG. PySpark uses lazy evaluation. Code only runs when an Action (`show()`, `write()`, `count()`) is invoked.
🚫
Trap 4: "OPTIMIZE deletes old Delta files" ❌ WRONG. OPTIMIZE merges small files into new large files, but leaves old files referenced in transaction log until VACUUM runs.

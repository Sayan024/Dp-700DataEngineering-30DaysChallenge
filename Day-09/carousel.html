Workspace Roles
WORKSPACE SECURITY→Workspace role permissions & management
Workspace Roles vs. Item Sharing
👥 Workspace Roles (Global)
Define user capabilities across ALL items within the workspace environment.
  • Admin: Add/remove workspace users + manage capacities
  • Member: Add users to lower roles + share items
  • Contributor: Build, edit, & delete items; no user management
  • Viewer: Read-only metadata & report consumption
🔗 Item-Level Permissions (Granular)
Share specific workspace resources without workspace-wide access permissions.
  • Read: General item metadata viewing permission
  • ReadData: Query database records (SQL Endpoint / Warehouse)
  • ReadAll: View raw unstructured data storage in OneLake Files

SQL Security
DATABASE LEVEL→Row-level & Column-level security configurations
Row & Column Level Security (RLS/CLS)
🗺️ Row-Level Security (RLS)
Filter row visibility dynamically using a TVF predicate function. Used to restrict region or group sales view access.
CREATE FUNCTION fn_securitypredicate(@Region sysname)
  RETURNS TABLE WITH SCHEMABINDING
AS
  RETURN SELECT 1 WHERE @Region = USER_NAME();
📊 Column-Level Security (CLS)
Restrict access to specific columns (like SSN, Salary) on a table without needing separate views.
-- Grant permissions only on non-sensitive columns
GRANT SELECT ON dbo.Employees
(EmployeeID, FirstName, LastName)
TO HrManager;

SQL ENGINE→Implement dynamic data masking
Dynamic Data Masking (DDM)
An on-the-fly masking mechanism that protects sensitive database fields
Mask FunctionMasking BehaviorExample (Original → Masked)
default()Blank or zero values depending on typeSayan → XXXX / 42.5 → 0.0
email()Exposes first letter & domain suffixsayan@test.com → sXXXX@XXXX.com
random(1, 9)Replaces numeric values with random bounds42 → random single digit
partial(2, "X", 2)Keeps first and last N letters, masks middleSayan → SaXaN
-- Apply masking to a credit card field
ALTER TABLE dbo.Customers
ALTER COLUMN CreditCard
  ADD MASKED WITH(FUNCTION = 'partial(0, "XXXX-XXXX-XXXX-", 4)');
💡
Unmask Permission: Admin/Owner roles see unmasked values by default. Grant viewers full visibility with GRANT UNMASK TO [user].

OneLake Security
STORAGE LEVEL→Unified folder & file level security configurations
OneLake Data Access Roles
Unified security model independent of SQL or Spark query engines
📁 Storage-Level Folders
Configure access rules directly on folders inside OneLake (`Tables/` or `Files/`).
  • Applies globally whether using Spark, SQL Endpoint, or Shortcuts
  • Saves you from writing duplicate security rules across database engines
  • Assign custom AD users or groups directly to roles
🔒 Access Level Types
  • Read: View folder metadata & read data
  • Write: Modify or upload files into folders
  • No Access: Folder remains completely hidden
🧠
Shortcut inheritance: Shortcuts inherit the folder-level permissions of their target path by default!

Purview & Labels
GOVERNANCE→Apply sensitivity labels & endorsement states
Governance: Endorsement & Labels
Ensuring data trustworthiness and leakage protection across Fabric
🏷️ Microsoft Purview Sensitivity Labels
Apply labels (Confidential, Public, Highly Restricted) to prevent data leaks.
  • Labels follow data inside the workspace
  • Lineage Inheritance: Semantic model labels propagate down to reports automatically
🌟 Item Endorsement States
  • Promoted: Alerts consumers to verified content. Available to anyone with workspace edit rights.
  • Certified: Strict verification. Can ONLY be enabled by tenant admins or workspace curators. Represents the single source of truth.

Exam Traps
DP-700 CAUTION→Security & governance traps
Top 4 Security Exam Traps ⚠️
🚫
Trap 1: "Contributors cannot add sensitivity labels"
❌ WRONG. Contributors have edit rights on items and can apply Purview sensitivity labels directly. Only Certifications require admin status.
🚫
Trap 2: "Promoting an item requires tenant administrator approval"
❌ WRONG. Anyone with write permissions on an item can **promote** it. Only **certifications** require tenant-authorized admin approval.
🚫
Trap 3: "Dynamic Data Masking encrypts the storage columns"
❌ WRONG. DDM does not change the physical data. It masks values on-the-fly during SELECT queries based on permission status.
🚫
Trap 4: "OneLake Data Access Roles apply only to Spark"
❌ WRONG. OneLake Data Access Roles are engine-agnostic storage filters. They protect folders from Spark, T-SQL, and shortcuts globally!

Files vs. Tables: The Structural Difference
OneLake structures every Lakehouse item into two distinct directory roots under the hood.
📁 The Files Section (Unmanaged)
🗃
Format Freedom

🛠
Metadata Management

🔀

🔥
Strict Format

✅
Schema Auto-Discovery
Valid Delta tables automatically register in catalog schemas
📊
Endpoint Visibility
Automatically queryable using the SQL Analytics Endpoint

Metadata Sync
How Auto-Discovery Metadata Works
Fabric constantly scans folders written inside the Tables directory to identify Delta log transactions.
📝
1. Spark Write Task
A PySpark Notebook writes a Delta table into the `Tables/` root path.
⚡
2. Log Scanner
Fabric detects the presence of the `_delta_log` transaction log folder immediately.
✅
3. SQL Mapping
The catalog registers the schema and exposes the table as a read-only view in SQL Endpoint.
⚠
Why Non-Delta Files Fail in Tables Folder
If you copy raw CSV, JSON, or standard Parquet (without transaction logs) into the Tables folder, the auto-discovery engine fails, and the item will **not** show up in the SQL endpoint. Keep raw formats in the Files folder!

Microsoft|SQL Endpoint
SQL Endpoint
Data Engineering›DP-700›SQL Analytics
Read-Only SQL
The SQL Analytics Endpoint
Every Lakehouse automatically exposes a read-only SQL endpoint to query Delta tables using T-SQL.
👁
Read-Only Queries
Supports full T-SQL queries, joins, filters, aggregations, Row-Level Security, and cross-lakehouse views.
❌
No DML Write Operations
You **cannot** execute INSERT, UPDATE, or DELETE statements. Write operations must use Spark.
💻 Example: Cross-Lakehouse Querying via SQL Endpoint
-- Join tables across different workspaces/lakehouses using 3-part names SELECT c.CustomerID, c.CustomerName, s.TotalAmount FROM SalesLakehouse.dbo.Customers c JOIN FinanceLakehouse.dbo.Transactions s ON c.CustomerID = s.CustomerID WHERE s.TransactionDate >= '2026-01-01';

Writing to Files vs. Tables in PySpark
Understanding the file paths and APIs used to target each section.
📁 Writing Raw Files (unmanaged files root)
# Write DataFrame as raw JSON files df.write \ .format("json") \ .mode("overwrite") \ .save("Files/raw_staging/sales.json")
📋 Writing Delta Tables (managed tables catalog)
# Write DataFrame as managed Delta table df.write \ .format("delta") \ .mode("overwrite") \ .saveAsTable("sales_managed")
💡
Important Paths Fact
Writing via `.save("Files/...")` targets the unmanaged storage layer. Writing via `.saveAsTable("table_name")` automatically targets the `Tables/` directory and creates Delta format metadata.

How to Access: ABFSS Paths
OneLake supports standard Azure Blob File System (ABFSS) URIs to access both Files and Tables.
🔗 URI Structures for Internal / External Tools
Folder Path type
Lakehouse Tables Endpoint
abfss://workspace_id@onelake.dfs.fabric.microsoft.com/lakehouse_id/Tables
Folder Path type
Lakehouse Files Endpoint
abfss://workspace_id@onelake.dfs.fabric.microsoft.com/lakehouse_id/Files
ⓘ
Multi-Engine Support
Because OneLake supports the ABFSS protocol, you can read and write files directly from Azure Databricks, Azure Synapse, or local Python sessions using standard cloud identity credentials.

Remember: Standard Parquet is NOT auto-discovered in Tables
This is a top exam trap! A standard Parquet file written inside the Tables folder will not sync with the SQL Analytics Endpoint. To trigger schema auto-discovery, the table must be written in the **Delta Lake format** (`_delta_log` metadata present).

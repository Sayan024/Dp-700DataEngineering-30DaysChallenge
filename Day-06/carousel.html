Spark Streaming
PROCESS DATA→Process data by using Spark Structured Streaming
Spark Structured Streaming Code Pattern
# Read stream from Delta or Event Hub
stream_df = spark.readStream \
  .format("delta") \
  .load("Files/bronze/sensor_data")

# Windowed aggregation
from pyspark.sql.functions import window, col, avg
agg_df = stream_df \
  .withWatermark("event_time", "10 minutes") \
  .groupBy(
    window(col("event_time"), "5 minutes"),
    col("sensor_id")
  ) \
  .agg(avg("temp").alias("avg_temp"))

# Write stream to Delta sink
query = agg_df.writeStream \
  .format("delta") \
  .outputMode("append") \
  .option("checkpointLocation", "Files/chk") \
  .table("silver.sensor_averages")
⚙️ 3 Output Modes
  • Append: Only new rows written to sink (Default for Delta)
  • Complete: Entire aggregated table rewritten every batch
  • Update: Only updated rows written to sink
📍
Checkpointing is Mandatory: Always provide checkpointLocation for fault tolerance and exactly-once processing guarantees!

KQL Analytics
PROCESS DATA→Process data by using KQL (Kusto Query Language)
KQL Streaming & Transformation Patterns
🔎 KQL In-Stream Transformation (Update Policy)
// Define update policy function
.create-or-alter function TransformTelemetry() {
  RawTelemetry
  | where Status == "ERROR"
  | project Timestamp, DeviceID, ErrorMessage
}

// Attach policy to target table
.alter table ErrorTelemetry policy update
@'[{"IsEnabled": true, "Source": "RawTelemetry", "Query": "TransformTelemetry()", "IsTransactional": true}]'
⚡ KQL Windowing Query (bin())
RawTelemetry
| where Timestamp > ago(1h)
| summarize
    AvgTemp = avg(Temperature),
    MaxTemp = max(Temperature)
  by DeviceID, bin(Timestamp, 5m)
💡
Update Policies: In KQL, Update Policies transform data automatically as it is ingested into raw tables, writing results to target tables seamlessly!

Exam Traps
DP-700 CAUTION→Streaming & RTI questions that trick candidates
Top 4 Streaming Exam Traps ⚠️
🚫
Trap 1: "Eventstreams requires a Data Pipeline" ❌ WRONG. Eventstreams is a standalone Fabric item that ingests, transforms, and outputs directly to Lakehouses or KQL DBs without pipelines.
🚫
Trap 2: "Tumbling window has overlapping steps" ❌ WRONG. Tumbling windows are fixed AND non-overlapping. Hopping windows have overlapping steps (hop interval).
🚫
Trap 3: "Querying OneLake Delta via KQL duplicates data" ❌ WRONG. OneLake Shortcuts in KQL Database point directly to external Delta Parquet files without copying data.
🚫
Trap 4: "Spark Streaming doesn't need checkpointing" ❌ WRONG. Checkpoint location is mandatory in Spark Streaming for fault recovery and state tracking.
